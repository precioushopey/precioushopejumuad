## Other pre-launch checks

- **Unique page titles, social share images, favicon:** every page has its own title and share image (see above). The favicon set is made from the logo with `npm run icons`.
- **Privacy policy:** `/privacy`, linked under the contact form. The site sets no cookies and the analytics are cookie-free, so there is no cookie banner. If cookies or tracking tools are added later, add a consent banner then.
- **Placeholder pages:** 11 projects are only "Coming Soon". They are marked `comingSoon: true` in `src/data/projects.ts`, so they are `noindex` and not in the sitemap.
- **Not applicable to this site:** fake reviews, metrics and customer counters (none exist; the Projects and Blog posts numbers are real counts), a made-with-AI tag (none), purple gradients (none), em dashes (none), a customer support page and terms and conditions (this is a personal portfolio with no customers or sales; the contact form covers enquiries).
- **Custom domain:** needs a domain you buy; see the notes at the end of this file.

## Speed (Lighthouse, mobile, local production build)

| Page | Before | After |
|---|---|---|
| Home | performance 57, layout shift 0.12, 1,417 KiB | 68–84, 0.00, 518 KiB |
| Blog post | 33, layout shift 0.93 | 63–69, 0.00–0.01 |
| SUBAY project | not measured | 50–59: two YouTube embeds pull in about 3 MB of video and player code |

Accessibility is 100 on Home and blog posts, SEO 100 on all of them. What changed: small WebP copies for tiles and avatars (`npm run thumbs`), width and height on fixed images, metric-matched fallback fonts, non-blocking font CSS, a loading skeleton, a vendor chunk, and cache headers. Scores vary by about 15 points from run to run on a laptop, so compare several runs. The one console error locally is the Vercel analytics script, which only exists on Vercel.

## Link previews and crawlers without JavaScript

Facebook, LinkedIn, WhatsApp, X and many crawlers do not run JavaScript. After every build, `scripts/prerender-meta.mjs` writes `dist/<route>/index.html` for all 34 pages, each with its own title, description, canonical link, `og:` and `twitter:` tags (including a per-page `og:image`) and structured data. Vercel serves those files before the catch-all rewrite, so a shared blog post shows its own preview. The wording rules there mirror `src/lib/seo.ts`; the text for the static pages is shared in `src/data/seo.json`.

## Adding a project or post

The sitemap, llms.txt and the page's title, description and structured data all come from the entry in `src/data/`. Add the entry, the route in `App.tsx` and the page file, and run `npm run build`.

## Still on you

- **Tell Google the site exists.** Add `https://precioushopejumuad.vercel.app` in Google Search Console, submit `/sitemap.xml`, and use "Request indexing" on the home page. Do the same in Bing Webmaster Tools.
- **A custom domain** (for example `precioushopejumuad.com`) ranks and gets linked more easily than a `vercel.app` address. If you add one, change `url` in `src/data/site.json`, `robots.txt` and the canonical/og tags in `index.html`.

## Backlink strategy

Backlinks have to come from other sites, so none of this can be done in code. In order of effort:

1. **Profiles you control:** put the site link on LinkedIn (Featured and Contact info), Facebook, Instagram, GitHub, Coursera, Credly, Figma Community and your Google Drive/Canva profiles.
2. **Places that already know you:** ask USTP, the ICpEP.SE student chapter, LGU Jasaan, OJT Connect and Roostercat to link to the project or page that features them.
3. **Share what you write:** post each blog entry on LinkedIn with a link, and cross-post longer ones to dev.to or Medium with a canonical link back to your site.
4. **Case studies:** SUBAY (Best Thesis and Best Prototype) is the strongest story. Send it to the university news page, campus media and Philippine tech and design communities.
5. **Directories and showcases:** Behance, Dribbble, Awwwards-style galleries, and the Philippine design/dev communities.
6. **Be useful in public:** answer questions on design and front-end communities and link to a relevant post when it truly helps.

Avoid paid link packages and link swaps; they can get a site penalised.

## Custom domain

Buy a domain, add it in Vercel (Project, Settings, Domains), and set the DNS records Vercel shows. Then change `url` in `src/data/site.json`, the Sitemap line in `public/robots.txt`, and the canonical and `og:` addresses in `index.html`, and redeploy. Keep the old `vercel.app` address redirecting to the new one (Vercel does this when you mark the new domain as primary).
